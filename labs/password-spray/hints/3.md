**Make it robust, not specific.** The hidden data uses different addresses, account names, timing, countries and clients from the practice data, so anything you hard-code from the practice data won't carry over. Build the rule from behaviour: a threshold on distinct failed accounts per address, then successes from those addresses. Return `UserPrincipalName` (plus `IPAddress` and `TimeGenerated` for the analyst), then check how many accounts you flag against the practice data. If you flag more than a handful, tighten the threshold.
